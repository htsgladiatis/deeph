# Andrey DS Harness V 0.5.7

Копия DeepSeek Harness с собственным слоем `lib/andrey` (загружается через
`resources/app/package.json` → `main: lib/andrey/boot.cjs`). Правки в этом каталоге
применяются сразу: `resources/app` распакован, asar пересобирать не нужно — только
перезапустить приложение.

## Дизайн

Пункт **«Дизайн»** в меню «…» (и `Ctrl+Shift+D`) открывает полноэкранный редактор
канваса: прямоугольники, эллипсы, текст, перо, выделение, перемещение, ресайз,
цвета, слои, undo/redo, несколько документов и автосохранение.

- Горячие клавиши: `V` выделение, `H` рука, `R` прямоугольник, `O` эллипс, `T` текст,
  `P` перо; `Space` + перетаскивание — панорама; колесо — зум к курсору;
  `Delete` удалить, `Ctrl+D` дублировать, `Ctrl+Z` / `Ctrl+Shift+Z` отмена/повтор,
  `Ctrl+S` сохранить, `Esc` закрыть панель.
- Документ: `~/.config` не используется — файлы в `%APPDATA%\andrey-ds-harness\design\<id>.json`
  (переопределяется `ANDREY_DATA_ROOT`). Хранится до 50 документов, запись атомарная.
- Модель для ИИ берётся из текущего выбора в чате; если имя неоднозначно (есть у обоих
  провайдеров), в селекте панели показывается суффикс провайдера.

### API (только loopback)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/design/docs` | список документов |
| GET | `/design/state?id=main` | документ |
| POST | `/design/state` | сохранить `{id, doc}` |
| POST | `/design/docs` | `create` / `rename` / `delete` |
| GET | `/design/models` | каталог моделей из профиля |
| POST | `/design/ai` | `{model, provider?, prompt, doc}` → `{ops, rejected}` |

Провайдер для `/design/ai` определяется по списку моделей профиля
(`dsh-home/profiles/desktop/cordis.patch.yml`): имя из `freepi` идёт в
`/freepi/v1/chat/completions`, из `freebuff` — в `/v1/chat/completions`. Токены и
устройство остаются внутри процесса: запросы уходят на собственный loopback-маршрут,
а не наружу.

Лог: `%APPDATA%\andrey-ds-harness\freebuff-route.log` (`design:save`, `design:ai`).

### Файлы

- `lib/andrey/design/ops.js` — схема документа и валидация (браузерная сборка).
- `lib/andrey/design/ops.cjs` — та же логика для Node.
- `lib/andrey/design/canvas.js` — движок канваса (рендер, ввод, история).
- `lib/andrey/design/panel.js` — панель, свойства, слои, документы, ИИ.
- `lib/andrey/design/panel.css` — стили (все классы `adz-`).
- `lib/andrey/ui-inject.cjs` — инжектит `panel.css`, затем `ops.js → canvas.js → panel.js → ui-renderer.js`.
- `lib/andrey/freebuff-route.cjs` — эндпоинты `/design/*`.

Все скрипты — обычные (без `import`/`export`), общаются через `window.AndreyDesign`.
## Пэт

В правом нижнем углу окна живёт «сгусток точек»: он показывает, чем занят агент, и
молчит, когда всё тихо. Состояния: `idle` — дышит, `working` — ускоренно вращается,
`replying` — пульсирует волной, `waiting` — тревожно мигает, `celebrate` / `error` —
короткие всплески. Состояние выводится из запросов страницы к LLM-маршрутам и лёгкого
опроса DOM; без сигналов пэт остаётся в `idle`.

- Пункт **«Скрыть пэта» / «Показать пэта»** в меню «…» — включение и выключение,
  выбор запоминается (`andrey-pet-enabled`).
- Перетаскивание — своя позиция (`andrey-pet-pos`), двойной клик — вернуть в угол,
  клик или Enter — короткая реакция и бабл со статусом.
- Файл: `lib/andrey/pet.js`, вставляется `ui-inject.cjs` вместе с `ui-renderer.js`.

## Браузер

Агент умеет работать в обычном браузере пользователя — Chrome, Edge, Brave или любом другом
на Chromium: открыть вкладку, прочитать страницу, кликнуть, напечатать, загрузить файл, снять
скриншот. Работа идёт в видимой вкладке: перед кликом или вводом агент подсвечивает элемент
рамкой и подписью, чтобы было видно, куда он целится. Управление идёт через расширение и
локальный мост, а не через удалённую отладку: Chrome 136+ игнорирует
`--remote-debugging-port` для профиля по умолчанию, поэтому единственный путь в тот браузер,
где пользователь уже вошёл во все сайты, — `chrome.debugger` из расширения.

### Установка расширения

1. В приложении: меню «…» → **«Браузер»** — там путь к папке расширения и шестизначный код.
2. Страница расширений браузера (`chrome://extensions`, `brave://extensions`, `edge://extensions`) →
   включить «Режим разработчика» → «Загрузить распакованное расширение» →
   выбрать `lib/andrey/browser/extension`.
3. Нажать на иконку расширения, в боковой панели ввести код из приложения.

Код одноразовый: после подключения расширение хранит только 64-символьный токен
(`%APPDATA%\andrey-ds-harness\browser\state.json`, права 0600). Кнопка «Отключить расширение»
в панели обнуляет токен и выдаёт новый код.

### Как это устроено

| Часть | Файл | Роль |
|---|---|---|
| MCP-сервер | `browser/mcp-server.cjs` | stdio-эндпоинт, монтируется профилем как `browser`; владеет мостом и состоянием |
| Мост | `browser/bridge.cjs` | WebSocket на 127.0.0.1 (порты 39160–39169), подтверждения, аудит |
| Инструменты | `browser/tools.cjs` | 17 инструментов `mcp__browser__*` |
| Политика | `browser/risk.cjs` | важность действия: низкая / средняя / высокая |
| Недоверенный текст | `browser/untrusted.cjs` | обёртка страницы, детектор инъекций |
| Расширение | `browser/extension/` | сервис-воркер, CDP-действия, боковая панель |
| UI | `ui-renderer.js` | пункт «Браузер» и панель |

Профиль получает запись `id: browser-bridge` при каждом запуске (`browser-profile.cjs`),
поэтому обновление приложения её не теряет.

### Инструменты

`status`, `tabs_list`, `tabs_open`, `tabs_close`, `tabs_focus`, `agent_stop`,
`page_snapshot`, `page_screenshot`, `page_click`, `page_type`, `page_press`, `page_scroll`,
`page_navigate`, `page_wait`, `page_extract`, `page_upload`, `page_console`.

Снимок страницы отдаёт узлы с `ref`, ролью, именем и координатами; текст страницы и консоль
обёрнуты в блок `<<<UNTRUSTED PAGE DATA>>>` и помечаются, если в них похоже на попытку
инструкций для модели. Пароли в снимок не попадают.

### Безопасность

- Мост слушает только `127.0.0.1` и принимает один клиент; чужой origin отвергается.
- Паринг: 6-значный код, 5 попыток в минуту, дальше 4408 и пауза.
- Агент видит только вкладки в своей группе «Andrey Agent»; прочие вкладки — `TAB_NOT_OWNED`.
- Каждый сайт имеет режим `ask` / `allow` / `block`; банковские и платёжные домены — всегда
  подтверждение. Загрузка файлов и переход на не-http(s) — всегда высокий риск.
- Подтверждение приходит в боковую панель расширения и живёт 120 секунд.
- `agent_stop` и кнопка «Пауза» останавливают агента немедленно; журнал действий хранится
  в `state.json` (последние 2000 строк, текст полей с секретами маскируется).

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ANDREY_DATA_ROOT` | `%APPDATA%\andrey-ds-harness` | корень данных; состояние браузера — в `browser/` |

Порты: мост занимает первый свободный из 39160–39169 и пишет его в `browser/bridge.json`;
панель находит его GET-запросом `/control/ping`. Если порт занят чужим процессом, мост
сдвигается на следующий — панель и расширение ищут порт сами.
## Провайдер Freebuff

Модели `freebuff` обслуживает собственный loopback-маршрут на `/v1/chat/completions`:
он поднимает официальный CLI в pty, выбирает модель в его пикере, отдаёт промпт
одной вставкой (bracketed paste) и читает ответ из транскрипта чата. Работает
строго через официальный клиент — сторонние клиенты Freebuff блокирует.

Сам CLI (`freebuff.exe`, 0.2.36) лежит в репозитории — `lib/andrey/freebuff/bin/` (Git LFS) —
и имеет приоритет над установленным в `~/.config/manicode`: отдельная установка не нужна.

Настройки (переменные окружения процесса приложения):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `FREEBUFF_CWD` | пусто | рабочий каталог агента; пусто — приватный `freebuff-runs/<account>/<ts>` |
| `FREEBUFF_PROMPT_CHARS` | `24000` | сколько символов разговора уходит в CLI (новые реплики приоритетнее) |
| `FREEBUFF_SYSTEM_CHARS` | `4000` | сколько символов системного промпта идёт преамбулой `[System]` (`0` — выключить) |
| `FREEBUFF_RUN_TIMEOUT_MS` | `600000` | предел одного прогона; по нему отдаётся частичный ответ |
| `FREEBUFF_QUEUE_TIMEOUT_MS` | `900000` | сколько запрос ждёт очереди на аккаунт |

Поведение отказов: детерминированные состояния (лимит часов, подтверждение
трат, вопрос агента, не найден CLI) возвращаются как `409`, обрыв клиента — `499`,
остальное — `502`. Гейт доверия к `.agents`/`mcp.json` в рабочем каталоге получает
явный ответ «нет», чтобы TUI не зависал. Промпт уходит в TUI как обычные нажатия
(чанками по 200 символов): bracketed
paste до composers доходит, но CLI 0.2.36 выбрасывает внутри него переводы строк
(проверено: вставленный код приходит одной строкой), поэтому переносы
склеиваются в пробелы. Из промпта вырезаются управляющие символы (ESC и прочие
C0, кроме `\n` и `\t`): ESC превратился бы в нажатие Escape и сбросил бы ввод.
Токенов CLI не отдаёт, поэтому `usage` в ответах — оценка по длине текста
(кириллица ≈2 символа на токен, остальное ≈4), а не реальные числа провайдера:
тарификация идёт часами, а не токенами. Лог: `freebuff:request` /
`freebuff:prompt` / `freebuff:prompt-flattened` / `freebuff:usage-estimated` /
`freebuff:done` (с `reason` и `cwd`) / `freebuff:failed`.

## Автоматическое сжатие контекста

Длинная сессия раздувает массив `messages`, пока провайдер не отклонит запрос
или агент не начнёт терять нить. Перед отправкой маршрут freePi
(`freepi-route.cjs`) сжимает историю до бюджетного числа токенов: сохраняются
системные инструкции, первая реплика с целью и самые свежие ходы; вырезанные
серединой ходы заменяются одной короткой пометкой. Вызов инструмента и его
результат переносятся только парой — разорвать пару означало бы получить ошибку
`tool_call_id`, то есть как раз тот сбой, которого сжатие и должно предотвратить.

Оценка токенов приблизительная. Дополнительного запроса к LLM нет: у freePi
одна заявка в полёте, и второй запрос упирался бы в те же гейты, которые маршрут
уже обходит.

Порог срабатывания — 190k по доле окна, но окно одно на промпт и ответ, поэтому
реальный триггер — `min(окно × 0.95, окно − вывод − 1000)`. У freePi-моделей окно
200k и ответ 32k: при 8192 «думающая» модель тратила весь бюджет на reasoning и
возвращалась пустой, а с 32k порог = `min(190000, 200000 − 32768 − 1000) = 166232`.
Больше контекста в 200k окне можно получить только уменьшив ответ; 190k контекста
требуют ответа меньше ~9k, то есть снова обрезанного размышления.

`compaction-profile.cjs` при старте пишет в `cordis.patch.yml` (запись
`compaction-basic`) `thresholdRatio: 0.95`, `headroomTokens: 1000` и
`maxTokens: 8192` (это cap сводки: без него бэкенд берёт `headroomTokens` = 1000
и режет её), а также зажимает `maxTokens` всех freePi-моделей до 32k — именно это
поле бэкенд вычитает из окна, а хост перезаписывал его из каталога (120k у
flash-моделей), из-за чего порог падал до 79k. Штатный порог бэкенда —
`min(окно × 0.8, окно − вывод − 65536)`; правка идемпотентна, существующие
`modelPolicies` не трогаются.

Отдельно про `413 {"code":"context_too_long"}` от freePi: он приходит не из-за текста.
В двух сессиях отказ случился ровно на первом запросе с новыми скриншотами — при
44–56k текста, из 6 и 12 картинок (1.7 и 3.5 МБ). Каждая картинка истории едет в
каждом теле заново, и провайдер считает их намного дороже нашей оценки (счётчик
контекста считает только ссылку на вложение). Поэтому `pi-profile.cjs` держит
бюджет картинок на провайдере: не больше 4 в запросе, до 1 МП и до 400 КБ каждая,
суммарно до 4 МБ. Старые вхождения `@deepseek-ai/dsh-compaction-image-offload`
заменяет текстовой пометкой и повторяет запрос — история диалога при этом цела.

Но и это не весь лимит: freePi режет по **размеру тела запроса**. В логе 413 пришёл
на теле 1 059 858 байт, а запросы до 869 028 байт проходили — то есть порог около
1 МиБ, и токенная оценка (75k) о нём ничего не знает. Поэтому маршрут
(`context-compress.cjs`, `shrinkImagesToLimit`) перед отправкой меряет тело: если
оно больше 900 КБ, самые старые картинки заменяются строкой-пометкой, пока тело не
влезет. Текст не режется — этим занимается токенный бюджет. Порог меняется
`ANDREY_REQUEST_MAX_BYTES`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ANDREY_CONTEXT_TOKENS` | `166232` | запасной бюджет истории freePi на маршруте; при превышении тело сжимается |
| `ANDREY_CONTEXT_ENABLED` | `1` | `0` — выключить сжатие, маршрут форвардит тело как есть |
| `ANDREY_REQUEST_MAX_BYTES` | `900000` | потолок тела запроса; выше него маршрут снимает самые старые картинки |

Пока история в бюджете, тело запроса уходит байт-в-байт без изменений. Событие
`freepi:context-compressed` в `freebuff-route.log` показывает размеры до/после
и число вырезанных сообщений. Событие `freepi:request-metrics` пишется на каждый
запрос (модель, `maxTokens`, число сообщений, байты, оценка токенов маршрута), а
`freepi:upstream-error` — на любой не-2xx от freePi вместе со статусом, кодом и
началом тела; пара этих строк и запись `usage` в сессии показывают, какое именно
число провайдер считает превышением. У Freebuff своя обрезка — `FREEBUFF_PROMPT_CHARS`
(см. выше), — поэтому отдельный слой ему не нужен.
